# Knowlume 路线调整提案：先完成科研日用闭环

> 日期：2026-10-04（Asia/Shanghai）  
> 状态：Proposed，供讨论；未替代 [roadmap](../roadmap.md)、accepted ADR 或接口契约。  
> 依据：[开发现状审视](2026-10-04-development-review.md)，基线 `Phase5` / `0c39f452004ed58b8ef3c8f11f560c09255b5494`。  
> 用户目标：个人科研阅读与知识积累优先，允许重新排列开发顺序。

## 1. 推荐方向与取舍

**推荐下一里程碑为“科研日用闭环”：让一个研究问题从论文/项目采集，经过记录、引用、关联、找回，再到回顾，能够连续完成。** 先修正已证实的接口问题和频繁操作断点，再推进更复杂的知识演化。

本次审视确认 Phase 5 修复及最终完成记录的远程门禁成立，不重开整个阶段；新发现作为后续改进处理。底层的稳定身份、角色区分、私有默认、事务恢复与只读 Web 都值得保留。

| 可选路线 | 收益 | 代价与适配性 | 本提案选择 |
|---|---|---|---|
| 立即完整推进原 Phase 6A | 补齐历史、合并、替代等生命周期能力 | 多文件写入与身份语义复杂，不能直接解决创建/编辑/检索之间的日常断点 | 保留，但拆分并后置高风险部分 |
| 先补科研日用闭环 | 直接降低每次阅读、记录、找回成本，尽快获得真实使用证据 | 需要少量跨既有阶段的 CLI/Web/文档改进 | **推荐** |
| 提前模型调用、语义检索或 MCP | 自动化潜力高 | 增加外发、评估、候选摄入和维护边界；当前缺少召回与效率基线 | 暂缓，仅先测量实际需求 |

这里的阶段顺序是建议，只有后续明确接受并同步权威文档后才生效。包发布仍有独立授权与门禁，不能因本提案自动执行。

## 3. 下一里程碑：科研日用闭环

### 3.1 用户交付结果

1. 从现有 Zotero 资料和项目 URL 建立可追溯 Source，并清楚区分缺条目、歧义和缺附件。
2. 创建有意义标题的阅读笔记或个人想法后，可以直接定位需要编辑的文件，不必由 ID 猜路径。
3. 用一份完整指南填写 human 内容、带 locator 的 fact 和跨笔记关联，知道哪些字段需要人工判断。
4. 编辑完成后，按显式步骤校验并刷新索引；搜索失败时获得针对当前状态的恢复指引。
5. 在 Web 中优先读正文，点击搜索结果到稳定 section，查看人类内容、事实引用及相关材料；审计信息仍可查看。
6. 明确当前 AI 是“已有候选的审核与晋升”，模型生成和候选接入是后续独立能力。

### 3.2 最小改动建议

- **机器错误：** 对现有支持 JSON 的命令统一参数解析错误的输出策略，先锁定缺 scope 复现，再覆盖代表性必填参数、非法值及未知选项。沿用 envelope v1；新错误代码在接口 owner 中记录，不在提案中发明第二套枚举。
- **笔记创建：** 建议新增可选 `--title`，默认行为保持兼容；建议新增 `note new --json`，返回对象 ID 和 vault 相对路径，方便编辑器/脚本定位。确切结果 shape 由新增版本化接口 schema 定义；创建过程不生成“人类观点”，不自动生成 fact 引用。
- **写作交接：** 给出标题、正文、fact 元数据及引用 locator 的最小真实示例；用 get 的相对路径打开编辑器。下一里程碑不新增通用 Web 写入，也不把 Obsidian 配置变成必需数据源。
- **编辑后检查：** 推荐流程固定为显式 lint → index build → search；版本不兼容时明确 rebuild。可以提供显式调用的演示工作流，但查询、页面加载和安装均不能隐式修复 vault 或索引。
- **只读展示：** 笔记正文与引用摘要前置；结构、路径、checksum 等移入可访问的折叠详情；搜索与适用的关系链接使用现有 section ID fragment；相关目标显示标题并保留 ID。
- **试用包：** 一份从初始化到回顾的中文指南、一个离线合成示例、真实 Zotero 接入的可重复检查步骤及独立记录模板。沿用现有 fixtures 和服务，不另建业务模型。

这些接口变化是建议，尚未实现或冻结。它们不要求改变 Note/Source 的 durable Contract v2；若实现发现必须改动 durable 格式，应先单独完成版本及迁移决策，而非借体验优化绕过流程。

### 3.3 实施顺序与依赖

| 步骤 | 工作 | 进入下一步的条件 |
|---|---|---|
| B0 | 接受路线取舍，将本里程碑及命令归属同步到 roadmap/interfaces；必要时新增 ADR | 新增接口、兼容范围、测试责任明确；本提案不自行成为规范 |
| B1 | 修复 R01，补机器错误回归 | 缺 scope 仍被拒绝，stdout 是可解析的单 envelope，未泄漏输入 |
| B2 | 定义 Note 创建结果 schema/正反 fixtures，补 title 与显式文件定位 | 旧调用行为兼容，新 JSON 有命令级证据，stable ID 与事务不变 |
| B3 | 完整写作/索引指引与只读阅读改进 | 有标题笔记可定位并完成编辑；长文 section 跳转与只读性实测通过 |
| B4 | 离线场景回放、用户限定范围的真实接入/编辑器试用 | 模拟、真实和不可验证项分开；记录阻塞与重复手工操作 |
| B5 | 全套、分发、隔离安装与受支持平台验收 | 按仓库既有门禁记录准确提交证据，同步 CLI ledger；无发布动作 |

后续实施需遵循既有契约变更顺序：决策 → schema → 模板（适用时）→ 正反 fixtures → 验收测试 → 生产实现；不改变 durable 文件时明确记录无迁移需求。新能力落地时同步 CLI ledger；本次审视没有新增或改变已交付命令，因此保持原账本不动。

### 3.4 验收标准

**自动化与安全：** 完整仓库测试、静态检查、wheel/sdist 审计、源码树外安装、生命周期及既定平台矩阵通过。新增 CLI 用法错误覆盖 stdout/stderr/退出码和 envelope schema。Web 全页/HTMX 数据一致、无写入；section 跳转不使用行号或标题推导新身份。原子写入、引用完整性、私有默认、AI 人工审核及未知依赖失败关闭保持有效。

**流程验收：** 使用两篇论文和一个项目来源，完成两篇 Literature、一篇 source-free Idea→Concept、一篇有至少两个关联对象的 Synthesis；人类正文由人填写。能记录一条有效 fact 引用，执行一次重复采集、一次外部编辑后的索引恢复、一次关系回查、一次中英文找回。另以合成 Artifact 演示审核、预览和冲突拒绝，不调用模型。

**使用验收：** 按单一指南从新 vault 完成上述流程，除填写笔记与事实 locator 外不需要到源码/测试中寻找使用方法；创建后立即知道文件位置；搜索命中一步到对应 section；失败提示能指向明确的下一项操作。记录必需手工步骤与工具切换，和本次发现逐项比较，不用测试数量代替效率改善。

**真实集成：** 在用户指定的测试资料范围中验证至少两篇可精确匹配的 Zotero Paper，其中一篇带可恢复 PDF；记录 Zotero/系统版本、附件 hash、一条不可用或歧义路径及 vault 不被失败操作修改的证据。模拟通过只允许宣布离线流程通过；真实条件未提供时保持这一验收项未完成，不把私人资料试用变成默认授权。

### 3.5 明确非目标

本里程碑不实现 merge/supersede/history、publish、模型 transport、语义/向量搜索、MCP、多智能体、云同步、Snippet 创建或完整原生阅读器；不新增 Web 写入权限，不绕过 Zotero 匹配及来源完整性条件，不修改包版本或进行发布。

## 4. 保留、提前、延后与取消

| 决策 | 内容 | 理由与重新评估条件 |
|---|---|---|
| 保留 | Contract v2、独立 vault、文件事实源、稳定身份、可重建索引、显式人工审核 | 本轮测试与关键路径支持其价值；没有证据需要整体重构 |
| 保留 | 分发/平台/安全门禁及 Phase 5 完成记录 | 完成条件已核验；新缺陷作为后续工作，不重写历史 |
| 提前 | 低成本的编辑交接、阅读展示与索引恢复；Phase 6A 的只读回顾 | 直接对应个人日常闭环，能复用已有服务与反向关系 |
| 延后 | 多文件合并、完整历史、自动整理 apply | 先积累真实重复/演化案例，冻结 actor、冲突与恢复行为 |
| 延后 | AI 生成与外部模型接入 | 先证明候选接入和人工审核流程可用，再定义数据释放边界 |
| 延后 | 发布与高级检索/MCP/图等 | 公开产出和召回需求尚无本轮用户实证；保持既有 Planned/Deferred |
| 取消本轮安排 | 大规模架构重写、重新设计持久模型、以阶段百分比衡量进度 | 缺少支持它们的证据，且会推迟可用流程；不等于永久取消未来能力 |

Book/Web 的 open/sync 和快照修复作为显式产品缺口记录；科研首要场景验证前不追加为下一里程碑必做项。Snippet 继续遵守现有“无期限延期，重新启用须 accepted ADR”的决定。

## 5. 后续决策与评估方式

完成下一里程碑后，以三项事实决定后续投入：用户能否持续使用、哪些步骤仍阻塞、哪些查询确实找不到已有材料。建议在用户自愿的连续两周试用中记录任务类型、失败原因和人工步骤，不收集私人正文或外发遥测；这只是试用建议，不在本次创建定时任务。

- 若主要障碍是回顾与关联，按 C 推进，只复用既有扫描与关系能力。
- 若主要障碍是候选接入，按 D 改进模板/校验与受控导入，不自动提前模型调用。
- 若出现明确规模延迟，先执行报告 R08 的测量，再决定缓存或增量方案；不得以提高速度为由返回陈旧索引结果。
- 若真实需求进入合并/替代或新的写入入口，先解决相关事务接口与 actor 决策，再进入 E；避免让局部分层偏差演变为第二套写入机制。
- 只有明确的公开知识产出或召回评测缺口出现时，分别重新评估 F 或 G；二者不能共享模糊的“智能化”完成标准。

正式接受本提案后，需要更新的权威文档包括 roadmap、interfaces 和相应阶段目标；只有行为所有权改变时才更新 chapter-map。任何 durable 兼容性变化需独立版本决策；任何 Git 写操作、远程触发或发布按用户授权和仓库规则执行。本次交付仅为报告与提案。
